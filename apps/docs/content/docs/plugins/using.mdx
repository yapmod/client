---
title: Using Plugins
description: Install, enable, update, and remove plugins.
---

Plugins add behavior to Yapin. Everything below happens on the **Plugins**
page inside the Yapmod settings group.

## Installing

- **From a URL** — _Add Plugin_ → _From URL_. Paste the folder URL that
  contains `plugin.json` and `plugin.js`; pasting the URL of either file
  works too. Enable _Check for updates_ if the plugin should be refreshed
  on every page load.
- **From code** — _Add Plugin_ → _From Code_. Paste JavaScript that returns
  an object with optional `onLoad`, `onUnload` and `settings` members.

Plugins are stored in this browser (`yapmod.plugins.v1`), and their code
runs with full access to the page, so only install plugins from authors you
trust.

## Managing installed plugins

Each card shows the plugin's name, author and description with:

| Control | Action                                                                   |
| ------- | ------------------------------------------------------------------------ |
| Switch  | Start or stop the plugin; the choice persists across reloads             |
| Gear    | Opens the plugin's settings, while it is running and exported `settings` |
| Refresh | Re-fetches a remote plugin (remote plugins only)                         |
| Pencil  | Edits the plugin                                                         |
| Trash   | Deletes the plugin; per-plugin storage is kept for a reinstall           |

The search box filters the list by name, author or description.

Remote plugins with _Check for updates_ enabled are refreshed once when the
page loads. A plugin that fails to start is switched off and reported with a
toast instead of retrying on every load.

## Client plugins

Client plugins are provided by the **application that runs Yapmod** rather
than installed by you: the embedding application registers them in code with
`YapmodClient.registerClientPlugin()` at startup. They share the plugin API
and lifecycle — `onLoad`, `onUnload`, `settings`, `onDispose` and per-plugin
storage — but they are never stored as installable records, never fetched or
evaluated, and cannot be edited, updated or deleted.

They do not appear on the Plugins page by default. Turn on **Show client
plugins** in _Yapmod → Settings_ to reveal a **Client plugins** section
below the community list:

- The setting is pure visibility. Hiding client plugins does not stop the
  ones that are running, and showing them works whether they are enabled or
  not.
- The search box filters both sections.
- A client plugin card has only a settings button (while running) and an
  enable switch, plus a `Client` label — no update, edit or delete actions
  and no safety warning.
- Disabling one stops it immediately and persists; enabling it again
  restarts it.

Whether a client plugin starts in the first place is decided by its
`defaultEnabled` flag and your explicit choice, which always wins across
reload. See [Client Plugins](/docs/plugins/client-plugins) for the
registration API and the full contract.
