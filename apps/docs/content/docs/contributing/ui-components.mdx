title: UI Components
description: Reference for the @yapmod/ui SolidJS components used in the Yapmod client.
---

The `@yapmod/ui` package provides SolidJS components that reproduce Yapin's native look and feel. Every feature panel in the client (settings, themes, plugins) uses these components. You should never use raw HTML form controls in the client codebase.

Import components directly from the package in your code:

```ts
import { Button, Switch, Input, Textarea, Select } from '@yapmod/ui';
```

These same components are also exposed through `YapmodClient.ui` so plugins can use them. If you are a plugin author looking for the full guide, see the [UI Components](/docs/development/ui-components) page in the Plugin Development section instead.

## Form controls

All form controls follow a consistent **controlled and uncontrolled** pattern:

- Pass `value` (or `checked` for Switch) to make the component **controlled**. Its state is driven entirely by the prop you pass.
- Pass `defaultValue` (or `defaultChecked`) for an **uncontrolled** component that manages its own internal state.
- `onChange` always receives the new value directly, not a DOM event object.

### Switch

A toggle switch that matches Yapin's `.switch` style. Under the hood, it renders a real `<input type="checkbox">` element with `role="switch"`, so keyboard interaction (Space to toggle) and focus rings work natively.

```tsx
import { Switch } from '@yapmod/ui';

// Controlled
<Switch checked={enabled} onChange={setEnabled} />

// Uncontrolled
<Switch defaultChecked={false} onChange={(v) => console.log(v)} />
```

**Props:**

| Prop             | Type                         | Description                       |
| ---------------- | ---------------------------- | --------------------------------- |
| `checked`        | `boolean`                    | Current state (controlled mode)   |
| `defaultChecked` | `boolean`                    | Initial state (uncontrolled mode) |
| `onChange`       | `(checked: boolean) => void` | Called when toggled               |
| `aria-label`     | `string`                     | Accessible label                  |

### Input

A single line text field that matches Yapin's `.input` style.

```tsx
import { Input } from '@yapmod/ui';

// Controlled
<Input value={name} onChange={setName} placeholder="Enter a name" />

// Uncontrolled
<Input defaultValue="" onChange={(v) => console.log(v)} />
```

**Props:**

| Prop           | Type                      | Description                                |
| -------------- | ------------------------- | ------------------------------------------ |
| `value`        | `string`                  | Current text (controlled mode)             |
| `defaultValue` | `string`                  | Initial text (uncontrolled mode)           |
| `onChange`     | `(value: string) => void` | Called on every keystroke                  |
| `type`         | `string`                  | Input type (`text`, `search`, `url`, etc.) |
| `placeholder`  | `string`                  | Placeholder text                           |
| `id`           | `string`                  | Element ID for label association           |

All standard `<input>` attributes like `disabled`, `maxlength`, and `inputmode` are passed through to the underlying element.

### Textarea

A multi line text field that matches Yapin's `textarea.input` style. It behaves like `Input` but supports vertical resizing.

```tsx
import { Textarea } from '@yapmod/ui';

<Textarea value={code} onChange={setCode} rows={12} spellcheck={false} />;
```

**Props:**

| Prop           | Type                      | Description                      |
| -------------- | ------------------------- | -------------------------------- |
| `value`        | `string`                  | Current text (controlled mode)   |
| `defaultValue` | `string`                  | Initial text (uncontrolled mode) |
| `onChange`     | `(value: string) => void` | Called on every keystroke        |
| `rows`         | `number`                  | Number of visible rows           |

All standard `<textarea>` attributes are passed through.

### Select

A dropdown that matches Yapin's `.dd-trigger` and `.dd-menu` style. The trigger is a button with `role="combobox"` and the option list is rendered in a portalled `listbox`. Keyboard navigation with arrow keys, Enter, and Escape matches Yapin's native dropdown behavior.

```tsx
import { Select } from '@yapmod/ui';

const options = [
  { value: 'always', label: 'Always' },
  { value: 'light', label: 'Light theme' },
  { value: 'dark', label: 'Dark theme' },
];

<Select options={options} value={mode} onChange={setMode} />;
```

**Props:**

| Prop           | Type                      | Description                                                  |
| -------------- | ------------------------- | ------------------------------------------------------------ |
| `options`      | `SelectOption[]`          | Options array with `value`, `label`, and optional `disabled` |
| `value`        | `string`                  | Selected value (controlled mode)                             |
| `defaultValue` | `string`                  | Initially selected value (uncontrolled mode)                 |
| `onChange`     | `(value: string) => void` | Called when selection changes                                |
| `placeholder`  | `string`                  | Text shown when no value is selected                         |
| `disabled`     | `boolean`                 | Disables the entire control                                  |
| `id`           | `string`                  | ID of the trigger button                                     |
| `aria-label`   | `string`                  | Accessible name                                              |

## Layout components

### Button

A button that matches Yapin's `.btn` style.

```tsx
import { Button } from '@yapmod/ui';

<Button variant="primary">Save</Button>
<Button variant="secondary">Cancel</Button>
<Button variant="danger" size="small">Delete</Button>
```

**Props:**

| Prop      | Type     | Description                                                    |
| --------- | -------- | -------------------------------------------------------------- |
| `variant` | `string` | `default`, `primary`, `accent`, `secondary`, `ghost`, `danger` |
| `size`    | `string` | `medium` (default) or `small`                                  |

### Panel

A card surface that matches Yapin's `.ss2-card` style.

```tsx
import { Panel } from '@yapmod/ui';

<Panel>Card content here</Panel>;
```

### Hint

Secondary helper text that matches Yapin's `.hint` style.

```tsx
import { Hint } from '@yapmod/ui';

<Hint>This setting applies to all themes.</Hint>;
```

### Icon

Renders an SVG icon from the bundled icon set.

```tsx
import { Icon } from '@yapmod/ui';

<Icon name="trash" size={16} />;
```

**Props:**

| Prop   | Type       | Description                           |
| ------ | ---------- | ------------------------------------- |
| `name` | `IconName` | Name of the icon from the bundled set |
| `size` | `number`   | Icon size in pixels                   |

## Injecting styles

The UI package bundles all component CSS. To inject it into the page, use the `injectStyles` function:

```tsx
import { injectStyles } from '@yapmod/ui';

// Injects the bundled stylesheet once
injectStyles();
```

Components use `yp-` prefixed class names only. Colors, hover states, and focus rings come from the bundled CSS. The CSS prefers host theme CSS variables like `--bg-side`, `--text`, and `--accent`, with `--yp-*` fallbacks for when those are not available.

## Tabs, badges, and icon buttons

These Solid components are available from `@yapmod/ui`, `yapmod.ui`, and
`YapmodClient.ui`. They use Yapin's theme variables with standalone fallbacks.

```tsx
import { createSignal } from 'solid-js';
import { Tabs, Badge, IconButton, Icon } from '@yapmod/ui';

function Friends() {
  const [tab, setTab] = createSignal('online');
  return (
    <Tabs
      label="Friends"
      variant="pills"
      value={tab()}
      onChange={setTab}
      options={[
        { value: 'online', label: 'Online' },
        {
          value: 'pending',
          label: (
            <>
              Pending <Badge>3</Badge>
            </>
          ),
        },
        { value: 'blocked', label: 'Unavailable', disabled: true },
      ]}
    >
      <p>Selected: {tab()}</p>
      <IconButton aria-label="Refresh friends" onClick={() => console.log('Refresh')}>
        <Icon name="refresh" />
      </IconButton>
    </Tabs>
  );
}
```

`Tabs` is controlled: supply a unique value for each option, keep `value` set to
an enabled option, and render the selected content in `children`. The default
`underline` variant matches Yapin's developer tabs; `pills` matches its friends
tabs. Left/Right arrows (including RTL), Home, and End select and focus enabled
tabs. `disabled` disables the whole tab list; individual options also accept it.
Labels accept Solid JSX, including badges. The panel is linked to the selected tab.

`Badge` renders Yapin's compact red notification count. Use `variant="mention"`
for the amber mention style. Supply an `aria-label` when the count needs context.

`IconButton` matches Yapin's 34px toolbar buttons with 20px icons. An `aria-label`
is required. `active` adds accent color and `aria-pressed` for toggle buttons;
`variant="danger"` adds the danger color. Native button props such as `disabled`
and `onClick`, plus `class` and `classList`, are supported. It defaults to
`type="button"` so it does not submit surrounding forms.
