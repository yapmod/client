Plugins add behavior to Yapin. A plugin is JavaScript that runs inside the Yapin page with
the same access as code you paste into the developer console. Yapmod can install a plugin
from a remote plugin folder or from JavaScript you paste or upload yourself.

You will find the plugin manager under **Yapin settings → Yapmod → Plugins**.

## What is on the page

- A search field that filters plugins by name, author, and description.
- **Add Plugin**, which opens the add form.
- A safety card with the plugin warning.
- One card per installed plugin, sorted by name. Each card shows the plugin's name, author,
  and description, with actions on the right:

| Action       | Shown when                                  | What it does                                       |
| ------------ | ------------------------------------------- | -------------------------------------------------- |
| **Settings** | The plugin is running and provides settings | Opens the plugin's own settings dialog.            |
| **Update**   | The plugin is remote                        | Fetches its folder again and applies any changes.  |
| **Edit**     | Always                                      | Opens the plugin's form with its current values.   |
| **Delete**   | Always                                      | Stops and removes the plugin after a confirmation. |
| **Enable**   | Always                                      | The switch that starts or stops the plugin.        |

## Install a remote plugin

Remote plugins are installed from a folder containing `plugin.json` and `plugin.js`.

1. Open **Add Plugin**. Leave **Local plugin** turned off.
2. Enter the **Plugin URL**. Point it at the folder, or paste the URL of either
   `plugin.json` or `plugin.js`; Yapmod trims it back to the containing folder.
3. Leave **Automatically update** on if you want Yapmod to fetch a fresh copy when Yapin
   loads. Turn it off if you want updates only when you press the update button.
4. Select **Fetch**.

Yapmod downloads the manifest and the script before saving anything, so a bad URL, invalid
JSON, or an empty script fails the install instead of leaving a half-installed plugin
behind. The new plugin starts **disabled**; turn on its switch when you are ready.

Remote downloads are subject to Yapin's Content-Security-Policy, which only allows a small
set of hosts. `raw.githubusercontent.com` is the practical host for plugins kept in a GitHub
repository.

### Remote plugin folder

```text
my-plugin/
├── plugin.json
└── plugin.js
```

`plugin.json` carries the metadata shown on the card:

```json
{
  "name": "Hello Yapin",
  "author": "you",
  "description": "Adds a greeting to the page.",
  "version": "1.0.0"
}
```

`plugin.js` contains the plugin code described in [Writing a plugin](#writing-a-plugin).

## Install a local plugin

Use this for a plugin you are developing or for a script someone shared with you.

1. Open **Add Plugin** and turn on **Local plugin**.
2. Fill in **Name**, **Author**, and optionally **Description**.
3. Paste the JavaScript into **Code**, or use **Upload JS** to load a file.
4. Select **Add**.

Name, author, and code are required. Like remote plugins, a new local plugin starts
disabled.

## Enable and disable plugins

The switch on a plugin card starts or stops it:

- Enabling evaluates the plugin and runs its `onLoad` hook. If the plugin throws or does not
  return a valid plugin object, it stays disabled and a toast reports the failure.
- Disabling runs the plugin's `onUnload` hook and every cleanup it registered with
  `yapmod.onDispose()`, then removes it from the running set.
- The enabled choice is saved. Enabled plugins start automatically the next time Yapin
  loads, and disabled plugins stay off.

Stopping a plugin never deletes its saved data.

## Update and edit

**Update** is available for remote plugins. It fetches `plugin.json` and `plugin.js` again
and compares them with the installed copy. If nothing changed, you get an "already up to
date" message and the plugin keeps running. If something changed, Yapmod stops the running
copy, saves the new one, and starts it again when it was enabled.

Remote plugins with **Automatically update** enabled are refreshed when Yapin loads, before
the rest of the plugins start.

**Edit** opens the same form used to add a plugin. For a remote plugin, Yapmod fetches the
new folder before stopping the running copy, so a failed fetch leaves the working plugin
untouched. Saving an edit restarts the plugin if it was enabled.

## Delete a plugin

Deleting asks for confirmation, stops the plugin if it is running, and removes it from the
list. Its per-plugin storage is intentionally kept, so reinstalling the same plugin can
recover its saved data.

## Plugin settings

A plugin can provide its own settings view. When a running plugin exports `settings`, a
settings button appears on its card. The view opens in a Yapmod dialog titled after the
plugin, for example "Hello Yapin Settings".

The plugin decides what to render: a DOM node, an HTML string, or a function returning
either. Async functions are supported, so a plugin can build its view lazily.

## Writing a plugin

`plugin.js` is an expression that evaluates to an object. The object may define three
optional members:

```js
({
  onLoad() {
    const element = document.createElement('div');
    element.textContent = 'Hello from a plugin';
    document.body.append(element);

    yapmod.onDispose(() => element.remove());
  },

  onUnload() {
    console.log('Plugin stopping');
  },

  settings() {
    return '<p class="hint">Settings can be HTML or a DOM node.</p>';
  },
});
```

The source may also be a function that returns the object. It receives the plugin API as its
argument:

```js
(yapmod) => ({
  onLoad() {
    yapmod.storage.loadedAt ??= new Date().toISOString();
    yapmod.flushStorage();
  },
});
```

| Member     | When it runs                                                     |
| ---------- | ---------------------------------------------------------------- |
| `onLoad`   | When the plugin is enabled and starts.                           |
| `onUnload` | When the plugin is disabled, updated, edited, or Yapmod unloads. |
| `settings` | When the user opens the plugin's settings.                       |

### The plugin API

Every plugin receives a `yapmod` object with this surface:

| Member           | Description                                                            |
| ---------------- | ---------------------------------------------------------------------- |
| `id`             | The plugin's stable id, also used as its storage key.                  |
| `manifest`       | The metadata from `plugin.json` or the local plugin form.              |
| `storage`        | A per-plugin object persisted between page loads.                      |
| `flushStorage()` | Writes `storage` to `localStorage`. Call it after changing the object. |
| `onDispose(fn)`  | Registers a cleanup that runs when the plugin stops or Yapmod unloads. |
| `showSettings()` | Opens the plugin's settings dialog, if it exported `settings`.         |

Plugins run in the page's own realm, so normal DOM APIs are available. Yapin's UI is
rendered by React, which may replace nodes a plugin inserts directly; prefer adding your
own container and cleaning it up through `onDispose`.

### Storage example

```js
({
  onLoad() {
    const count = (yapmod.storage.count ?? 0) + 1;
    yapmod.storage.count = count;
    yapmod.flushStorage();
    console.log(`Loaded ${count} time(s)`);
  },
});
```

Storage is stored per plugin under `yapmod.plugins.data.v1`. It is local to this browser
and is not removed when the plugin is deleted.

## Safety

Plugins are not sandboxed and there is no permission model. They run with full access to
the page, its data, and its network requests. Only install plugins from authors you trust,
and review the code of anything you install locally.

## Troubleshooting

| Problem                                | What to check                                                                                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A plugin will not stay enabled         | Open the console. The code must evaluate to an object, and `onLoad` must not throw.                                                                        |
| A remote install fails                 | Confirm the URL points at a folder with `plugin.json` and `plugin.js`, the files are reachable, the JSON is valid, and the host is allowed by Yapin's CSP. |
| The settings button is missing         | The plugin must be running and must export `settings`.                                                                                                     |
| A plugin stops after reloading Yapin   | Its saved enabled state is restored, but a plugin that fails to start is marked disabled again. Check the console for its error.                           |
| An update says the plugin is current   | The fetched script and manifest are identical to the installed copy.                                                                                       |
| Yapin breaks after installing a plugin | Disable the plugin first, then delete it if the problem persists, and reload the page.                                                                     |

Plugins are stored in `localStorage` under `yapmod.plugins.v1`. See
[Installing Yapmod](/docs/guide/installing#where-your-data-lives) for backups and clearing
site data.

Looking for visual customization instead? See [Themes](/docs/guide/themes).
