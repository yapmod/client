## Prerequisites

- Node.js 22 or newer
- [pnpm](https://pnpm.io) 12 (the repository pins it via `packageManager`)

## Install

```bash
pnpm install
```

## Commands

| Command             | What it does                                             |
| ------------------- | -------------------------------------------------------- |
| `pnpm dev`          | Rebuilds the client bundle on every source change.       |
| `pnpm build`        | Builds the production client bundle.                     |
| `pnpm typecheck`    | Type-checks every workspace package (no build required). |
| `pnpm lint`         | Runs Oxlint across the repository.                       |
| `pnpm format`       | Formats the repository with Oxfmt.                       |
| `pnpm format:check` | Checks formatting without writing.                       |
| `pnpm docs`         | Serves this documentation site locally.                  |
| `pnpm docs:build`   | Builds the documentation site.                           |

## Trying the bundle

For an end-user walkthrough of loading and unloading the client, see
[Installing Yapmod](/docs/guide/installing).

There is no dev server and no simulated host page. You work against the real Yapin page:

1. `pnpm build`, or `pnpm dev` to rebuild on every change.
2. Open Yapin in the browser.
3. Paste the contents of `apps/client/dist/yapmod-client.js` into the developer console,
   or serve the file and load it with a script tag.
4. Check `YapmodClient.state` (it reports `ready`), then open Yapin's settings and look
   for the Yapmod section. `YapmodClient.dispose()` removes everything Yapmod added;
   reloading the page does the same.

With `pnpm dev` running, re-run the injected script after each rebuild to pick up
changes. The guard on `globalThis.YapmodClient` makes repeated injections safe: while the
client is loaded you get the existing handle back, and after a `dispose()` the next
injection starts a fresh runtime.
