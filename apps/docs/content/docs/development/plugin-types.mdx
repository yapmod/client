title: Plugin Types
description: Understand the difference between user-installed and client-registered plugins.

Yapmod supports two types of plugins. Understanding the difference between them will help you know how your plugin will be loaded, managed, and distributed.

## User installed plugins

These are plugins that you, as a user, manually add to your Yapmod instance. This is the most common type of plugin and the one you will encounter if you are building something for yourself or sharing it with others.

### How they work

The process is straightforward:

1. Get the plugin’s import URL or download its JavaScript bundle.
2. In **Plugins → Add Plugin**, select **URL** to fetch the URL or **Local** to upload the file.
3. Yapmod evaluates the plugin and loads it into your current session.
4. The plugin is saved to your local Yapmod configuration, so it persists across page reloads.

### Key characteristics

- **You install them manually**. There is no automatic discovery or installation system. You choose each plugin to install.
- **They live in your browser**. The plugin source and its settings are stored in your browser's `localStorage`.
- **They are per user**. Each user manages their own set of plugins. Plugins are not shared between users automatically.
- **Each plugin has its own storage**. Every plugin gets an isolated storage space backed by `localStorage`, so its data survives page reloads.

<Callout type="info">
  When you delete a user installed plugin, Yapmod intentionally keeps its storage. This means if you
  reinstall the same plugin later, all your saved data is still there.
</Callout>

## Client registered plugins

These are plugins that are built into the Yapmod client itself. They are registered in code and loaded automatically every time Yapmod starts. You do not need to do anything to enable them.

### How they work

1. The plugin code is written as part of the Yapmod client source code.
2. It is registered programmatically during the Yapmod bootstrap process.
3. The plugin loads automatically every time Yapmod injects into the page.

### Key characteristics

- **They are built in**. These plugins ship with Yapmod and are always available.
- **No installation needed**. They load automatically without any user action.
- **Part of the Yapmod codebase**. They are developed and maintained as part of the Yapmod project itself.
- **They use the same API**. Client registered plugins use the exact same `YapmodPluginApi` as user installed plugins. There is no difference in what they can do.

### When to use each type

- **User installed plugins** are for community creations, personal customizations, and anything you want to share and distribute on your own.
- **Client registered plugins** are for core functionality that should always be available to every Yapmod user. These are maintained as part of the Yapmod project.

## Comparing the two

Here is a quick overview of the key differences:

| Feature      | User installed             | Client registered       |
| ------------ | -------------------------- | ----------------------- |
| Installation | URL or file                | Automatic on startup    |
| Distribution | Catalog or file            | Bundled with Yapmod     |
| Maintenance  | Managed by the user        | Maintained by Yapmod    |
| Storage      | Per plugin localStorage    | Per plugin localStorage |
| API access   | Full `YapmodPluginApi`     | Full `YapmodPluginApi`  |
| Removal      | User can disable or delete | Always present          |
