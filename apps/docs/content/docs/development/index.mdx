Welcome to the development section. This is where we dive into everything you need to know about building Yapmod plugins, from the basic concepts to the complete API reference.

## What you will learn

Here is what we will cover in this section:

- **Fundamentals**. The skills and tools you should be comfortable with before writing a plugin, including JavaScript, TypeScript, and browser developer tools.
- **How plugins work**. The plugin lifecycle from start to stop, how Yapmod loads and runs your code, and how the evaluation process works.
- **The Plugin API**. Every method and property available to your plugin, from reactive storage and DOM observation to UI helpers and toast notifications.
- **UI Components**. All the built in SolidJS components like Switch, Input, and Select, plus how to use them with the builder for clean import syntax.
- **Plugin types**. The difference between plugins you install yourself and plugins that are built into the Yapmod client.
- **Reverse engineering**. How to inspect the Yapin interface, find the right DOM elements, and understand the patterns you will work with.
- **Distribution**. How plugins are shared and loaded, and what Yapmod does not provide in terms of a marketplace or discovery system.

## Two ways to build a plugin

There are two approaches to building a Yapmod plugin:

1. **Using the starter repo** (this is what we recommend). You clone a pre configured repository that already has the Yapmod plugin builder set up. This lets you write TypeScript and SolidJS the natural way, and produces a ready to upload plugin with a single command.
2. **Writing it manually**. You write your plugin as a raw JavaScript expression that returns the plugin object, without any build tool. This works, but you will need to handle bundling, compilation, and formatting yourself.

We recommend the starter repo approach for almost everyone. The manual approach exists for reference, but the builder tool and built in API give you a much better development experience.

## Why use the built in Plugin API

You could technically write a plugin that does everything by manually inspecting and manipulating the DOM. But Yapmod provides a Plugin API that makes your life much easier. The API methods are:

- **More performant**, because they are optimized and integrated with Yapmod internal systems
- **Easier to use**, because reactive storage, DOM observation, and UI helpers are all provided out of the box
- **More reliable**, because they handle cleanup and disposal automatically when your plugin stops

Use the built in API whenever you can. If you are ever unsure how to use a particular method, look at the existing plugin code for examples. The API is designed to be the foundation your plugins are built on.

## Where to start

If you are new to this, begin with [Fundamentals](/docs/development/fundamentals) to make sure you have the right background. Then move on to [How Plugins Work](/docs/development/how-plugins-work) to understand the plugin lifecycle before we dive into the API details.
