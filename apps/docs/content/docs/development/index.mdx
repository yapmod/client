A plugin is a small program that runs while Yapmod is active. It can add a composer tool, show information beside a draft, register a settings page, or respond to the selected conversation. Yapmod supplies the integration points and shared UI; your code supplies the behavior.

## Start with something you can see

The first tutorial builds a **draft character counter**. It needs no server or DOM selectors, and you can verify it immediately by typing in a conversation. The next guide adds a saved setting to the same plugin.

## Understand the pieces

Your **source** exports a function returning lifecycle hooks. The **builder** compiles TypeScript and Solid JSX into a single JavaScript expression. The **client** evaluates that expression and calls `onLoad` when the plugin starts. Inside the plugin, `yapmod` is the API for that particular instance; it owns registrations and storage.

Plugin metadata comes from the installation form or remote `plugin.json`. In the starter, maintain it in the plugin's `package.json`. You do not need to put a manifest in the object returned by your source function.

## Move on to your own idea

[Choose an integration](/docs/development/choosing-an-api) before inspecting Yapin's DOM. Built-in registrations handle host replacements and remove their UI when the plugin stops. If you need something outside those integrations, [working with the host DOM](/docs/development/reverse-engineering) explains the extra responsibilities.

You only need basic JavaScript to begin. [Core concepts](/docs/development/fundamentals) introduces the small amount of Solid reactivity used in these guides. Keep the [API reference](/docs/development/plugin-api) nearby for method signatures; it is a lookup resource, not a prerequisite for the tutorial.
