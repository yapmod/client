Yapmod provides a set of SolidJS components through `@yapmod/ui` that reproduce Yapin's native look and feel. You get buttons, switches, inputs, dropdowns, layout components, and more. Use them inside your plugin to build interfaces that look like they belong on the page.

## Accessing components

There are two ways to access UI components, depending on how you build your plugin.

### With the builder (recommended)

When you use `@yapmod/builder` (the `yapmod build` and `yapmod dev` commands), you can import components using normal ES module syntax:

```tsx
import { Switch, Input, Select } from '@yapmod/ui';

export default function (yapmod) {
  // Components work normally. The builder rewrites the imports at build time.
}
```

Here is what happens behind the scenes: the builder automatically rewrites `import ... from '@yapmod/ui'` to reference the shared `yapmod.ui` object at runtime. This means you write clean import syntax in your source code, but the final bundle uses the host's shared components. You get no duplicate SolidJS bundles and no extra CSS.

The same rewriting applies to `solid-js`, `solid-js/web`, and `solid-js/store`:

```tsx
import { createSignal } from 'solid-js';
import { render } from 'solid-js/web';
import { Button, Input } from '@yapmod/ui';
```

All of these imports are rewritten by the builder to use the shared instances (`yapmod.solid`, `yapmod.solidWeb`, `yapmod.ui`) instead of bundling separate copies.

### Without the builder (manual)

If you write your plugin as a raw JavaScript file without using the builder, you access components directly through the `yapmod.ui` object:

```js
export default function (yapmod) {
  const { Switch, Input, Select } = yapmod.ui;

  // Use SolidJS through yapmod.solid
  const { createSignal } = yapmod.solid;
}
```

<Callout type="info">
  The builder approach is strongly recommended. It gives you TypeScript support, JSX compilation,
  and clean import syntax, all handled automatically without any extra configuration.
</Callout>

All component prop types (`ButtonProps`, `SwitchProps`, `InputProps`, `SelectProps`, and so on) are importable from `@yapmod/types` if you want typed component usage. See the [Type Safety](/docs/development/type-safety) page for the complete list of available prop types.

## Form controls

All form controls follow a consistent **controlled and uncontrolled** pattern:

- Pass `value` (or `checked` for Switch) to make the component **controlled**. Its state is driven entirely by the prop you pass.
- Pass `defaultValue` (or `defaultChecked`) for an **uncontrolled** component that manages its own internal state.
- `onChange` always receives the new value directly, not a DOM event object.

### Switch

A toggle switch that matches Yapin's `.switch` style.

<SwitchPreview />

```tsx
import { Switch } from '@yapmod/ui';

// Controlled
<Switch checked={enabled} onChange={setEnabled} />

// Uncontrolled
<Switch defaultChecked={false} onChange={(v) => console.log(v)} />
```

**Props:**

| Prop             | Type                         | Description                       |
| ---------------- | ---------------------------- | --------------------------------- |
| `checked`        | `boolean`                    | Current state (controlled mode)   |
| `defaultChecked` | `boolean`                    | Initial state (uncontrolled mode) |
| `onChange`       | `(checked: boolean) => void` | Called when toggled               |
| `aria-label`     | `string`                     | Accessible label                  |

### Input

A single line text field that matches Yapin's `.input` style.

<InputPreview />

```tsx
import { Input } from '@yapmod/ui';

<Input value={name} onChange={setName} placeholder="Enter a name" />;
```

**Props:**

| Prop           | Type                      | Description                                |
| -------------- | ------------------------- | ------------------------------------------ |
| `value`        | `string`                  | Current text (controlled mode)             |
| `defaultValue` | `string`                  | Initial text (uncontrolled mode)           |
| `onChange`     | `(value: string) => void` | Called on every keystroke                  |
| `type`         | `string`                  | Input type (`text`, `search`, `url`, etc.) |
| `placeholder`  | `string`                  | Placeholder text                           |

All standard `<input>` attributes like `disabled`, `maxlength`, and `inputmode` are passed through to the underlying element.

### Textarea

A multi line text field that matches Yapin's `textarea.input` style.

<TextareaPreview />

```tsx
import { Textarea } from '@yapmod/ui';

<Textarea value={code} onChange={setCode} rows={12} spellcheck={false} />;
```

**Props:**

| Prop           | Type                      | Description                      |
| -------------- | ------------------------- | -------------------------------- |
| `value`        | `string`                  | Current text (controlled mode)   |
| `defaultValue` | `string`                  | Initial text (uncontrolled mode) |
| `onChange`     | `(value: string) => void` | Called on every keystroke        |
| `rows`         | `number`                  | Number of visible rows           |

### Select

A dropdown that matches Yapin's `.dd-trigger` and `.dd-menu` style.

<SelectPreview />

```tsx
import { Select } from '@yapmod/ui';

const options = [
  { value: 'always', label: 'Always' },
  { value: 'dark', label: 'Dark mode' },
];

<Select options={options} value={mode} onChange={setMode} />;
```

**Props:**

| Prop           | Type                      | Description                                        |
| -------------- | ------------------------- | -------------------------------------------------- |
| `options`      | `SelectOption[]`          | Options with `value`, `label`, optional `disabled` |
| `value`        | `string`                  | Selected value (controlled mode)                   |
| `defaultValue` | `string`                  | Initially selected (uncontrolled mode)             |
| `onChange`     | `(value: string) => void` | Called when selection changes                      |
| `placeholder`  | `string`                  | Text shown when no value is selected               |

## Layout components

### Button

A button that matches Yapin's `.btn` style.

<ButtonPreview />

```tsx
import { Button } from '@yapmod/ui';

<Button variant="primary">Save</Button>
<Button variant="secondary">Cancel</Button>
```

**Props:**

| Prop      | Type     | Description                                                    |
| --------- | -------- | -------------------------------------------------------------- |
| `variant` | `string` | `default`, `primary`, `accent`, `secondary`, `ghost`, `danger` |
| `size`    | `string` | `medium` (default) or `small`                                  |

### Panel

A card surface that matches Yapin's `.ss2-card` style.

<PanelPreview />

```tsx
import { Panel } from '@yapmod/ui';

<Panel>Card content here</Panel>;
```

### Hint

Secondary helper text that matches Yapin's `.hint` style.

<HintPreview />

```tsx
import { Hint } from '@yapmod/ui';

<Hint>This setting applies to all themes.</Hint>;
```

### Icon

Renders an SVG icon from the bundled icon set. The available icons are: `settings`, `puzzle`, `trash`, `palette`, `upload`, `refresh`, `plus`, `pencil`, and `close`.

<IconPreview />

```tsx
import { Icon } from '@yapmod/ui';

<Icon name="trash" size={16} />;
```

**Props:**

| Prop    | Type     | Description                                       |
| ------- | -------- | ------------------------------------------------- |
| `name`  | `string` | Icon name (`settings`, `puzzle`, `trash`, etc.)   |
| `size`  | `number` | Width and height in pixels (default: 16)          |
| `label` | `string` | Accessible label (without it, icon is decorative) |

## Settings layout

The settings layout components handle Yapin's CSS classes and spacing conventions for you, so you can build consistent settings pages without writing boilerplate. Use them together to compose a complete settings page.

### SettingsPage

The top level wrapper for a settings page. It renders the page title as an `<h2>` element and an optional description below it.

<SettingsPagePreview />

```tsx
import { SettingsPage } from '@yapmod/ui';

<SettingsPage title="My Plugin" description="Configure my plugin settings">
  {/* Sections and settings go here */}
</SettingsPage>;
```

**Props:**

| Prop          | Type          | Description                          |
| ------------- | ------------- | ------------------------------------ |
| `title`       | `string`      | Page title rendered as `<h2>`        |
| `description` | `string`      | Optional description below the title |
| `children`    | `JSX.Element` | Nested content                       |

### Section

A grouped block with a section heading. It renders a `.section-label` with consistent top margin spacing.

<SectionPreview />

```tsx
import { Section } from '@yapmod/ui';

<Section label="Appearance">{/* Settings rows go here */}</Section>;
```

**Props:**

| Prop       | Type                  | Description                                            |
| ---------- | --------------------- | ------------------------------------------------------ |
| `label`    | `string`              | Section heading text                                   |
| `spacing`  | `"normal" \| "large"` | Top margin: `18px` (normal, default) or `22px` (large) |
| `children` | `JSX.Element`         | Nested content                                         |

### SettingRow

A single setting row with a label, optional hint text, and a control element. It renders the `.toggle-row` pattern with the label and hint on the left and the control on the right.

<SettingRowPreview />

```tsx
import { SettingRow } from '@yapmod/ui';

<SettingRow label="Dark mode" hint="Use dark theme">
  <Switch checked={dark()} onChange={setDark} />
</SettingRow>;
```

**Props:**

| Prop       | Type                    | Description                                      |
| ---------- | ----------------------- | ------------------------------------------------ |
| `label`    | `string`                | Setting label                                    |
| `hint`     | `string \| JSX.Element` | Optional description below the label             |
| `children` | `JSX.Element`           | Control component (Switch, Button, Select, etc.) |

### SettingText

A read only setting row that displays a text value. This is useful for showing information like version numbers or file paths.

<SettingTextPreview />

```tsx
import { SettingText } from '@yapmod/ui';

<SettingText label="Version" hint="Current version" value="v1.0.0" />;
```

**Props:**

| Prop    | Type                    | Description                            |
| ------- | ----------------------- | -------------------------------------- |
| `label` | `string`                | Setting label                          |
| `hint`  | `string`                | Optional description below the label   |
| `value` | `string \| JSX.Element` | Read-only value displayed on the right |

### Divider

A horizontal separator line between sections. It renders a styled `<hr>` element that uses CSS variables for the border color.

<DividerPreview />

```tsx
import { Divider } from '@yapmod/ui';

<Divider />;
```

## Example: a complete settings panel

Here is how all these components look together in a real plugin that uses the builder:

<SettingsExamplePreview />

```tsx
import { createSignal } from 'solid-js';
import {
  SettingsPage,
  Section,
  SettingRow,
  SettingText,
  Divider,
  Switch,
  Input,
  Select,
  Button,
  Hint,
} from '@yapmod/ui';

export default function (yapmod) {
  return {
    manifest: {
      name: 'My Plugin',
      author: 'Me',
      description: 'Demonstrates UI components',
      version: '1.0.0',
    },
    start(api) {
      api.settings.registerSection({
        id: 'my-plugin',
        label: 'My Plugin',
        icon: 'settings',
        render: () => {
          const [enabled, setEnabled] = createSignal(true);
          const [name, setName] = createSignal('');
          const [theme, setTheme] = createSignal('default');

          return (
            <SettingsPage title="My Plugin" description="Configure my plugin settings">
              <Section label="General">
                <SettingRow label="Enabled" hint="Toggle the plugin on or off">
                  <Switch checked={enabled()} onChange={setEnabled} />
                </SettingRow>

                <SettingRow label="Display name">
                  <Input value={name()} onChange={setName} placeholder="Your name" />
                </SettingRow>
                <Hint>Enter your display name</Hint>

                <SettingRow label="Theme" hint="Choose a color theme">
                  <Select
                    value={theme()}
                    onChange={setTheme}
                    options={[
                      { value: 'default', label: 'Default' },
                      { value: 'nord', label: 'Nord' },
                      { value: 'gruvbox', label: 'Gruvbox' },
                    ]}
                  />
                </SettingRow>
              </Section>

              <Divider />

              <Section label="Info">
                <SettingText label="Version" hint="Current version" value="v1.0.0" />
              </Section>

              <div style={{ marginTop: '1rem' }}>
                <Button variant="primary">Save</Button>
              </div>
            </SettingsPage>
          );
        },
      });
    },
  };
}
```

The builder compiles all of this into a single `.js` file where every `import` statement is rewritten to use the shared `yapmod` API. You do not need to bundle SolidJS or `@yapmod/ui` yourself.
