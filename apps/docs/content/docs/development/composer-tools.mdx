---
title: Composer tools
description: Add composer actions with captured draft, selection and conversation context.
---

Use `yapmod.composer.registerTool` in a plugin’s `onLoad` hook. Yapmod mounts a native button beside the composer toolbar and removes it when the plugin stops. Plugins targeting older clients can check `typeof yapmod.composer?.registerTool === 'function'` before registration.

```tsx
import type { ComposerToolContext } from '@yapmod/types';

export default function () {
  return {
    onLoad() {
      yapmod.composer.registerTool({
        id: 'draft-length',
        label: 'Check draft length',
        icon: 'pencil',
        onActivate({ length, maxLength, focus }: ComposerToolContext) {
          const count = maxLength === null ? String(length) : `${length} / ${maxLength}`;
          yapmod.ui.showToast(`Draft length: ${count}`);
          focus();
        },
      });
    },
  };
}
```

## Tool options

| Option       | Meaning                                                                                                                                                     |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`         | Stable string scoped to your plugin. Registering it again replaces the previous action in place.                                                            |
| `label`      | Accessible name, button tooltip and visible overflow label. Use an action such as “Check draft length”.                                                     |
| `icon`       | An `IconSource` (built-in name or registered icon reference) or a Solid render function returning decorative JSX. Keep custom artwork within the icon area. |
| `onActivate` | Synchronous or async function called once per activation.                                                                                                   |

Built-in icons are `settings`, `puzzle`, `trash`, `palette`, `upload`, `refresh`, `plus`, `pencil` and `close`. For reusable SVG artwork, use [`api.ui.registerIcon`](/docs/development/plugin-api#apiuiregistericonname-definition). You can also pass a function such as `icon: () => <span>¶</span>`. The button label provides its accessible name.

## Composer context and placement

The callback receives the current draft length in UTF-16 code units, matching the native textarea. `maxLength` is the native maximum or `null` when unlimited. `focus()` returns focus to the originating input. The context is captured when the user chooses the action, including when the picker is open and the draft has changed.

Wide composers show tools in registration order. A narrow composer groups them under **Composer tools**, which opens a dialog of labeled actions. Each composer measures its own width, so a thread composer and a channel composer can use different layouts on the same page. Enter and Space activate the focused button. Escape closes the picker and restores focus to the opener.

## Cleanup

Registration returns an early disposer. Calling the disposer after replacing the same ID leaves the replacement active. Unloading or hot reloading a plugin cleans up its tools automatically. When Yapin replaces a composer, Yapmod moves the available actions to the new instance.

## Insert text into the originating draft

`context.insertText(text)` replaces the selection captured when the tool was activated. With a collapsed selection, it inserts at that caret. Text before and after the selection is preserved; the caret ends after the inserted text. Moving the selection while a plugin dialog is open does not change the insertion position. The operation updates Yapin’s React draft state and never submits or sends a message. It does not steal focus; call `context.focus()` when closing your dialog.

```ts
const result = context.insertText(savedReply);
if (!result.ok) {
  const messages = {
    'draft-changed': 'Your draft changed. Open the reply tool again.',
    'stale-target': 'This composer is no longer active. Open the reply tool again.',
    'max-length': 'This reply would exceed the message length limit.',
    'not-editable': 'This composer cannot be edited right now.',
  };
  yapmod.ui.showToast(messages[result.reason], 'error');
} else {
  context.focus();
}
```

A changed draft is rejected rather than overwritten or silently appended to. Activate the tool again to capture the new draft and selection. After a successful insertion changes the draft, the old context also rejects subsequent insertions. Length checks use the current native `maxlength`, in UTF-16 code units, after normalizing CRLF and CR line endings to LF; oversized text is never truncated. Disabled and read-only inputs reject insertion.

Contexts expire when their tool is removed or replaced, the client is disposed, the input or an ancestor is removed or moved, or navigation occurs (including a switch away and back). They never fall back to another textarea. `focus()` also does nothing for a stale context. Navigation invalidation is conservative: even a history update on the same page requires a fresh activation.

For clients predating this API, check `typeof context.insertText === 'function'` and show an upgrade message if it is unavailable.

## Rewrite a selection or apply a template

`draft` is the immutable text at activation. `selection.start` and `selection.end` are UTF-16 offsets into that text (an emoji can occupy two code units). `replaceSelection(text)` has the same behavior as `insertText(text)`; `replaceDraft(text)` replaces the entire captured draft. Both use every insertion guard described above, including after asynchronous work. They preserve host attachments and reply state and never send messages.

```ts
// A local rewrite of just the selected text.
const selected = context.draft.slice(context.selection.start, context.selection.end);
const result = context.replaceSelection(selected.toUpperCase());
if (!result.ok) yapmod.ui.showToast(`Rewrite failed: ${result.reason}`, 'error');

// In a separate tool activation, build a whole-draft template.
const templateResult = context.replaceDraft(`Summary:\n${context.draft}\n\nNext steps:\n`);
if (!templateResult.ok) yapmod.ui.showToast(`Template failed: ${templateResult.reason}`, 'error');
```

`channelId` identifies the originating Yapin conversation, including server channels, DMs and group conversations. It is captured, not reactive. Yapmod verifies the host composer's draft key against its enclosing conversation; it does not infer identity from URLs, labels or the globally selected channel. Unsupported or ambiguous host contexts return `null`. Do not interpret `null` as a shared conversation or use it as a storage key. No messages, channel metadata or member information are exposed.

Slash commands receive the same captured `channelId` alongside `args` and `signal`:

```ts
yapmod.commands.register({
  name: 'template',
  description: 'Remember a template for this conversation',
  execute({ args, channelId, signal }) {
    if (signal.aborted || channelId == null) return;
    yapmod.storage[`template:${channelId}`] = args;
    yapmod.ui.showToast('Template saved for this conversation.');
  },
});
```

Commands consume and clear their invocation through the existing host integration before execution; they do not send the slash text. The command context does not grant draft editing. For older clients, feature-detect `replaceDraft` and treat an absent `channelId` like `null`.
