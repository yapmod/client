---
title: Message context menu actions
description: Place a plugin action in Yapin’s message menu and read its loaded message data.
---

A message’s right-click menu and its **More** button offer the same set of plugin actions. Use `yapmod.contextMenus.registerAction('message', action)` to contribute a labeled item. The client supplies the selected message to your callback each time the menu opens.

## Open a message details dialog

```tsx
export default function () {
  return {
    onLoad() {
      yapmod.contextMenus.registerAction('message', {
        id: 'message-details',
        label: 'Message details',
        icon: 'settings',
        onSelect: async ({ messageId }) => {
          const result = await yapmod.messages.getLoaded(messageId);
          if (result.status !== 'found') {
            yapmod.ui.showToast(
              result.status === 'not-loaded'
                ? 'This message is no longer loaded.'
                : 'Message access is unavailable.',
              'error',
            );
            return;
          }
          yapmod.ui.openModal({
            title: 'Message details',
            content: () => <p>{result.message.text ?? 'Text unavailable'}</p>,
          });
        },
      });
    },
  };
}
```

`message` is the supported target kind. Its read-only `messageId` is the ID on the message row when the menu opened. Yapmod checks that the original row still belongs to the current chat and carries the same ID before dispatching your action.

## Action options

| Option              | Meaning                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| `id`                | Stable, nonempty identifier unique within the running plugin. Two plugins can use the same ID. |
| `label`             | Visible text and accessible name of the menu item.                                             |
| `icon`              | Optional `IconSource`: a built-in name or an `api.ui.registerIcon()` reference.                |
| `visible(context)`  | Optional synchronous predicate. Return `true` to show the item for this message.               |
| `onSelect(context)` | Called once for the selected message. Accepts a synchronous or asynchronous callback.          |

Keep visibility checks inexpensive and free of side effects. For example, `visible: ({ messageId }) => savedIds.has(messageId)` shows an action only for messages in your saved set. Yapmod checks visibility again on activation.

## Ordering and cleanup

Plugin actions follow the native items in registration order. The host menu provides keyboard navigation. A plugin callback can open a Solid dialog after the menu closes.

The returned function removes the action early, including from an open menu. Yapmod unregisters actions automatically when a plugin stops and discards registrations from a failed setup. On older clients, check for `yapmod.contextMenus?.registerAction` before registering an optional feature.

## Read loaded message data

`await yapmod.messages.getLoaded(messageId)` reads only Yapin's existing message cache,
including its extra-message cache. It never requests history or changes a message.

- `found` includes a detached, frozen `message` snapshot. `id` is always present.
  Validated `text`, `authorId`, `channelId` and `createdAt` are optional. Empty text
  remains an empty string. `createdAt` preserves the host timestamp and precision.
- `not-loaded` means the ID was not in the current cache. It does **not** establish
  that a message was deleted, does not exist, or cannot be accessed.
- `unavailable` means host discovery/access failed or the returned record could not
  be identified. Try again later; do not treat this as a cache miss.

`attachments` is undefined when unknown, empty when the host reports no attachment,
and otherwise contains the host's single attachment with a storage `path` and optional
`name`, byte `size`, pixel `width` and `height`. A path is not a resolved download URL.
No URLs, profiles, channel details or missing metadata are fetched or inferred.
Malformed optional fields are omitted. Snapshots do not update after edits; read again.

Invalid/empty IDs and reads after the plugin stops reject. A pending read also rejects
if the plugin stops during discovery. On older clients, check `yapmod.messages?.getLoaded`
before using this optional capability. Keep asynchronous reads in `onSelect`, not `visible`.
