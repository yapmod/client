## Publish your catalog

The [Plugin Starter](/docs/setup/starter-repo) includes a GitHub Actions workflow for distribution. Each public repository publishes its own catalog. Its maintainer chooses which plugins appear there.

1. In your public repository, enable GitHub Actions. In **Settings → Pages**, choose **GitHub Actions** as the publishing source.
2. Push your plugins to the default branch. You can also select that branch under **Actions → Plugin catalog → Run workflow**.
3. Once the workflow succeeds, open the deployment URL in its summary. Share this page with users who want to browse or download your plugins.

The workflow type-checks and builds the collection before publishing. It deploys the catalog to Pages and writes the generated files to the `plugin-dist` branch using the repository’s built-in token. Allow the workflow to write to that branch. Each push to the default branch refreshes both destinations.

## Install a plugin by URL

1. On the author’s catalog page, copy the **Yapmod import URL** for the plugin you want.
2. In Yapmod settings, open **Plugins → Add Plugin** and select **URL**.
3. Paste the link into **Plugin URL** and select **Fetch**.

The import URL points to a public GitHub Raw folder such as `https://raw.githubusercontent.com/OWNER/REPO/plugin-dist/weather/`. Yapmod fetches `plugin.json` for metadata and `plugin.js` for the code. Share this URL for a specific plugin, or share the Pages URL for the whole collection.

## Install a download

Choose **Download JavaScript** in the catalog. In **Plugins → Add Plugin**, select **Local**, choose **Upload JS**, enter the plugin details and select **Add**.

## Share a collection

A collection is a JSON index that lists plugins together inside Yapmod. Host an `index.json` (or another JSON filename) on a host Yapin allows, such as `raw.githubusercontent.com`, and share its direct URL.

In **Plugins → Add Plugin**, select **Collection**, paste the index URL and select **Add Collection**. The collection appears as a collapsible group in Plugins, with its name, description, plugin count, and a Collection label. Expand it to browse and install individual entries. The Plugins search also searches collections and opens matching groups. Use the collection’s **•••** actions to **Refresh** its listing or **Remove collection**. Collections are cached in this browser, so reopening Yapin does not require downloading them again. A failed refresh keeps the previous listing. Removing a collection keeps its installed plugins: they appear outside the group, or in another collection that still lists them.

Adding a collection only downloads metadata. **Install** fetches the selected plugin's `plugin.json` and `plugin.js` through the normal plugin manager. The plugin starts disabled with automatic updates off; enable it directly inside the collection, or use its edit action to change its update preference. Installed entries use the normal plugin controls, including settings, update, edit, delete, and enable/disable. If a plugin appears in several collections, each group controls the same installation. Standalone plugins remain outside collection groups.

### Index format (version 1)

```json
{
  "schemaVersion": 1,
  "name": "My plugins",
  "description": "A collection of small Yapin improvements.",
  "plugins": [
    {
      "name": "Weather",
      "author": "Your name",
      "description": "Show the current weather.",
      "url": "./weather/"
    },
    {
      "name": "Another plugin",
      "url": "https://raw.githubusercontent.com/OWNER/OTHER-REPO/plugin-dist/example/"
    }
  ]
}
```

`schemaVersion`, the collection `name`, and the `plugins` array are required. Each plugin requires a `name` and `url`; descriptions and authors are optional. An empty array is allowed. Plugin URLs must use HTTP(S), either directly or relative to the index's final URL after redirects. They point at folders containing `plugin.json` and `plugin.js`; URLs to either of those files also work. Duplicate plugin folders and malformed entries reject the index rather than replacing a saved listing with incomplete data.

The index's names and descriptions are for browsing. Installed plugin metadata comes from its own `plugin.json`. Publish the index alongside your built plugin folders (for example, on `plugin-dist`) so `./weather/` resolves correctly. The starter's HTML catalog alone is not a collection index; publish this JSON file explicitly.

## Security considerations

<Callout type="error">
  Only install plugins you trust. Since there is no review process, any plugin can do anything that
  browser JavaScript can do. Always read the source code before installing a plugin from an unknown
  source.
</Callout>

Plugins run in the same context as the Yapin page. This means they have access to the DOM, localStorage, and any data visible on the page. A malicious plugin could read your messages, modify the interface in harmful ways, or exfiltrate data. Always verify the plugin's source code before installing it.
