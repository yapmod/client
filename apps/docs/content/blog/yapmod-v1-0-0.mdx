On November 19, we shipped Yapmod 1.0. If you read [the first post](/blog/welcome-to-yapmod), you’ll remember why I wanted to pull the client out of the old desktop app. With this release, you can take the part I missed most, load it into the Yapin tab you already have open, and make a change you can actually see. [Download version 1.0.0 on GitHub](https://github.com/yapmod/client/releases/tag/v1.0.0).

## Start with something small

Say you like the colors in Yapin but wish the settings cards had a little more breathing room. A stylesheet is enough for that. Open **Settings → Yapmod → Themes**, add your CSS file and switch it on. You can also paste a few rules directly if you’re still figuring out what looks right.

The small detail I like here is what happens on the second try. If the padding looks a bit generous, edit the file and upload it again under the same name. Yapmod replaces the installed copy and remembers that you had it switched on. You can leave the panel open, look at the cards again and decide whether to keep the change. [Add your first theme](/docs/get-started#add-a-theme).

## Give a plugin a place in settings

A theme is enough for the spacing change. Suppose you also want a “Compact layout” switch so someone else can choose how much space they like. That’s a good first plugin. The client gives you a switch that looks at home in Yapin, a section in the sidebar to put it in, and storage to remember the answer.

In the v1 API, the switch can save its value with `yapmod.storage.compact = true`. A Solid component reading that preference picks up the change. If someone turns the whole plugin off, its registered section disappears from settings. When they enable it again, their choice is still there. Those are details every plugin author would otherwise have to work out for themselves. [Browse the settings controls](/docs/development/ui-components).

## What it feels like to work on one

The difference is easiest to notice when you’re fiddling with a label. Turn on hot reload in Yapmod’s settings, start the builder and open Yapin from its local control page. Leave those two tabs open. Each time you save, the builder sends the updated plugin to the same Yapin tab. You can read the label in context, shorten it by a word and look again. [Set up hot reload](/docs/setup/hot-reloading).

Since tagging 1.0.0, we’ve also worked on what happens when an edit goes wrong. On the main branch, a failed reload leaves the last working plugin in place, and a failed save in the plugin editor now tells you what happened. Both fixes landed after the release download. [Hot-reload fix](https://github.com/yapmod/client/pull/70) · [Editor fix](https://github.com/yapmod/client/pull/69).
